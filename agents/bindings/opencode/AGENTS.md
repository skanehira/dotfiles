# OpenCode グローバル指示

このファイルは `~/.config/opencode/AGENTS.md` に symlink され、OpenCode の全セッションで読まれる。
ハーネスの正本は `dotfiles/agents/` に 1 セットだけあり、Claude Code / Codex / OpenCode が**同じ実体**を読む。

**このファイルがあると `~/.claude/CLAUDE.md` は自動では読まれない。** OpenCode はグローバル指示を
`~/.config/opencode/AGENTS.md` → `~/.claude/CLAUDE.md` の順に探し、**最初に見つかった 1 つだけ**を
読む (実測: `packages/opencode/src/session/instruction.ts` の `globalFiles` ループが `break` する)。
したがって共通の正本は下の指示に従って**自分で Read する**。

## 共通ハーネスの適用

- リポジトリやタスクの内容によらず、すべてのセッションで必ず `~/.claude/CLAUDE.md` を Read し、その内容 (評価関数、不変則、エスカレーション、オーケストレーションとモデル階層、実装時の手順) に従う。
- これは Claude Code 専用の文書ではない。正本は `dotfiles/agents/AGENTS.md` で、`~/.claude/CLAUDE.md` はその symlink である。
- `~/.claude/rules/...` も同じ正本 (`dotfiles/agents/rules/`) への symlink で、OpenCode 用に別の版は無い。**ルールは Claude 綴りで書かれているので、下の「Claude 綴りの読み替え」に従って読む。**
- スキルも共有である。`~/.agents/skills/<name>` は `dotfiles/agents/skills/<name>` への symlink で、Claude Code が読む `~/.claude/skills/<name>` と同じ実体を指す。

## 基本方針

- ユーザーが明示しない限り、日本語で回答する。
- コード変更前に関連ファイルを読み、既存の設計・命名・運用パターンに合わせる。
- 検索には `rg` / `rg --files` を優先する。
- auth files、tokens、caches、logs、histories に含まれる秘密情報を露出・commit・要約しない。
- `~/.local/share/opencode/` の sqlite state、logs、caches はローカルマシンに留める。
- `~/dev/github.com/skanehira/dotfiles` で作業する場合、このリポジトリの構成・セットアップ・Nix 運用・sudo の扱い・作業手順は `~/dev/github.com/skanehira/dotfiles/CLAUDE.md` を参照する。

## OpenCode に配られているもの

| 要素 | 配布先 | 正本 | 反映のタイミング |
| --- | --- | --- | --- |
| このグローバル指示 | `~/.config/opencode/AGENTS.md` | `agents/bindings/opencode/AGENTS.md` | 即反映 (symlink) |
| スキル | `~/.agents/skills/<name>` | `agents/skills/<name>` | 中身の編集は即反映。**追加と削除は `drs` / `hms` が要る** (個別 symlink の張り直し) |
| subagent | `~/.config/opencode/agents/*.md` | `agents/subagents/*.md` を書式変換したもの | **変更も追加も `drs` / `hms` が要る** (Markdown の再生成) |
| ルール | `~/.claude/rules/` を絶対パスで直接 Read する (OpenCode 側に複製は無い) | `agents/rules/` | 即反映 (symlink) |
| Spark の provider 設定 | `~/.config/opencode/opencode.json` | `agents/bindings/opencode/opencode.json` | 即反映 (symlink) |
| TUI のキーバインド | `~/.config/opencode/tui.json` | `agents/bindings/opencode/tui.json` | 即反映 (symlink)。TUI からの theme 切り替えも repo 側へ書き戻る |

**hooks はこの表に無い。** OpenCode はシェル hooks を持たない (JS プラグイン API しか無く、コマンドに
stdin を渡さず stdout も解釈しないので deny するゲートには使えない)。そもそもこのハーネスは
機械ゲートを 1 本も持っていないため、移植すべきものも無い (→「hooks は OpenCode では動かない」節)。

`~/.claude/skills` は読まない。`OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1` で切ってある
(`nix/modules/home/codex.nix`)。同じスキルの実体が `~/.claude/skills` と `~/.agents/skills` の
両方から見えるため、切らないと同名スキルが二重に列挙される (OpenCode は同名スキルをマージしない)。

スキルは除外リストで絞っている。`utility-session-profile` は Claude Code のセッションログしか
読まないため配られない (`nix/modules/home/codex.nix` の `claude_only_skills`。このリストは
`~/.agents/skills` を埋める activation が持つので、Codex と OpenCode の両方に効く)。

配布されているか自分で確かめる:

```bash
# パイプに繋ぐと出力が途中で切れるので必ずファイルに落とす (実測: パイプだと毎回違う件数になる)
opencode debug skill > /tmp/s.json && rg -c '"name"' /tmp/s.json
ls ~/.agents/skills                        # スキルが dotfiles への symlink で並ぶ
ls ~/.config/opencode/agents               # subagent の .md がある
opencode agent list                        # subagent が出る
readlink -f ~/.claude/rules                # dotfiles の agents/rules に解決する
echo $OPENCODE_DISABLE_CLAUDE_CODE_SKILLS  # 1 でなければターミナルを開き直す
```

`~/.config/opencode/agents/*.md` は生成物で、frontmatter の先頭に `# generated by ...` が入り
`drs` / `hms` のたびに上書きされる。**手で編集しない。**手で流し直すときは次の 1 本。

```bash
~/.claude/scripts/sync-subagents.ts ~/dev/github.com/skanehira/dotfiles/agents/subagents \
  ~/.config/opencode/agents opencode
```

## Claude 綴りの読み替え

スキル・subagent・ルールの本文は Claude Code 向けの語彙で書かれている。OpenCode 上では次のように読み替える。

| Claude Code の記述 | OpenCode での読み替え |
| --- | --- |
| `AskUserQuestion` | `question` |
| `TodoWrite` / `TaskCreate` / `TaskUpdate` | `todowrite` |
| `Agent` ツール | `task` |
| `Skill` ツールでの呼び出し | 対応するスキルをスキル名で呼ぶ |
| `Explore` (subagent 型) | 組み込みの `explore` |
| `general-purpose` (subagent 型) | 組み込みの `general` |
| `WebFetch` | `webfetch` |
| `WebSearch` | web search |
| `run_in_background` | バックグラウンド実行 (同期 spawn は逐次実行で代替) |
| `claude -p` | `opencode run` |
| `CLAUDE.md` (指示ファイル名として) | `AGENTS.md`。ただし共通の正本を指す記述は `~/.claude/CLAUDE.md` をそのまま Read する |
| `~/.claude/rules` | 同じパスをそのまま読む (同一実体) |
| `~/.claude/skills` | `~/.agents/skills` |
| `~/.claude/agents` | `~/.config/opencode/agents` |
| `~/.claude/scripts` | 同じパスをそのまま実行する (同一実体。Claude Code 用のパスに見えても同じマシン上のファイル) |
| `~/.claude/knowledge-profile.md` | 同じパスをそのまま読み書きする (同一実体。`utility-doc-reading` が使う) |
| `plan mode` | `plan` エージェント |

## 読み替えで吸収できないもの

- **呼び出し例の引数の形は Claude Code のもの**。ツール名は読み替えられるが、`question({ questions: [...] })` のような例に出てくる引数の構造は Claude Code のスキーマのまま。**自分のツールのスキーマに合わせて読み替える**
- **`question` は非対話実行 (`opencode run`) では使えない**。その場合は `~/.claude/CLAUDE.md`「エスカレーション」の自律モード規定に従い、前提と選択の根拠を出力に明示して前進する
- **`task` に渡す `model` / `subagent_type`** は subagent の生成物に表現手段が無く落ちるので、**親のモデルを継承する**。定義が無い名前を指している場合は組み込みの `explore` / `general` で代替するか、同一セッション内で逐次実行して報告に明記する
- **スキルの相互呼び出し**で `slide-plugin:*` / `document-skills:*` のような Claude 専用プラグインのスキルが指定されている場合は、その旨を伝えて代替手段を提案する
- **`chrome-devtools` の MCP ツール**: **未配布**。`opencode.json` に MCP の設定が無い。必要になったら報告して指示を仰ぐ
- **skill の frontmatter** (`allowed-tools` / `model` / `argument-hint` 等): OpenCode は `name` / `description` / `license` / `compatibility` / `metadata` 以外を無視する。制約として書かれている内容は本文と同じ重みで自分で守る
- **`/model` コマンドと `Fable` / `Mythos` の tier 名**: Claude Code 固有。セッションモデルの切り替え手段と世代名は自分のランタイムのものに読み替える
- **`ScheduleWakeup`**: OpenCode に相当機能が無い。バックグラウンドタスクの追跡は自分から状態を取りに行く運用で代替する

ここに無い Claude 固有の記述に出会ったら、勝手に読み替えず**その旨を報告して指示を仰ぐ**。

## 3 者で表現できない subagent の属性

変換スクリプト (`dotfiles/agents/scripts/sync-subagents.ts`) が Markdown に出すのは
`description` と `mode: subagent` の 2 キーだけである。正本の frontmatter にある以下は
OpenCode 側に届かない。

- **`name`**: OpenCode は subagent 名を**ファイル名から決める** (`configEntryNameFromPath`)。正本の `name` がファイル名になるので識別は保たれるが、frontmatter には出さない
- **`tools` (ツールの許可リスト)**: OpenCode の `tools` は真偽値マップで、正本のカンマ区切り文字列とは形式が違う。制限が要るなら本文に禁止事項として書く
- **`model`**: OpenCode は `provider/model-id` の形を要求し alias が使えない。世代交代に追従できないので生成物に書かない。subagent は**親のモデルを継承する**
- **`context: fork`**: 相当概念が無い

## hooks は OpenCode では動かない

**OpenCode に hooks は配られていない。** そもそもこのハーネスは機械ゲートを 1 本も持っていないうえ、
OpenCode はシェル hooks 自体を持たない (JS プラグイン API しか無く、しかもコマンドに stdin を渡さず
stdout も解釈しないため deny するゲートには使えない)。

dev-impl の修正ラウンド上限は**自律遵守**である。
