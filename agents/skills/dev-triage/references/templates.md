# dev-triage の雛形

- 種別: テンプレート
- 生成者: dev-triage (手順 3 の振り分けで `needs-human` にする行と、手順 5 の「失敗したとき」)
- 消費者: `needs-human` の issue に回答する人。dev-triage の次の起動 (末尾の `<!-- dev-triage -->` より後の人のコメントを回答として読む。SKILL.md 手順 2「以前の整理への回答」)

コメントは 1 件の issue につき 1 回の整理で 1 つだけ書く。読む人は、この issue のことを覚えていない前提で書く (`~/.claude/rules/core/collaboration.md`「質問・提案の形式」)。どの型でも、末尾の `<!-- dev-triage -->` を消さない。

## 判断を求めるコメント

人か顧客の判断・回答・手作業が要る issue と、`事業・運営` のラベルが無いリポジトリの事業・運営の issue に書く。

```markdown
**<何を決めてほしいかを 1 文で>**

<なぜ AI が決められないかを 1〜3 文。何と何が食い違っているか、誰の判断が要るか>

- A (推奨): <案>。<選んだときに起きること>
- B: <案>。<選んだときに起きること>

回答をこの issue にコメントで書いて `needs-human` を外すと、次の dev-triage の起動で回答を読んで整理し直します。

<!-- dev-triage -->
```

判断が複数あるときは **Q1. / Q2.** と番号を振る。

## 質問・確認のコメント

質問・確認・人手の検証だけの issue (実装の作業が無いもの) に書く。

```markdown
**この issue は回答 (または確認) で用が済むものと判断しました: <何に答えれば済むかを 1 句で>**

<なぜ実装の作業が無いと判断したかを 1〜2 文>

回答をこの issue にコメントで書いたら、issue を close してください。回答の結果として実装が必要になったときは、そのことをコメントに書いて `needs-human` を外すと、次の dev-triage の起動で整理し直します。

<!-- dev-triage -->
```

## 情報を求めるコメント

判定する材料が足りない issue に書く。

```markdown
**整理に必要な情報が足りません: <足りないものを 1 句で>**

<何が分からないと、何が決められないかを 1〜3 文>

- <書いてほしいこと 1。例: 起きた画面と操作の手順>
- <書いてほしいこと 2。例: 期待していた結果>

本文かコメントに書いて `needs-human` を外すと、次の dev-triage の起動で整理し直します。

<!-- dev-triage -->
```

## 緊急のコメント

緊急枠に当たる issue に書く。採点はせず、本文の `## 優先度` に `緊急枠` と書いてある。

```markdown
**緊急枠に当たる可能性があります: <起きていることを 1 句で>**

<緊急枠のどれに当たるか (業務停止、データの誤り、情報漏えい) と、本文のどの記述からそう判断したかを 1〜3 文>

- A: 緊急として扱う。人が直接対応するか、`needs-human` を `needs-design` に付け替えてください。本文に緊急枠と書いてあるので、次の dev-feat-spec の起動で先頭に設計されます
- B: 緊急ではない。そうコメントに書いて `needs-human` を外すと、次の dev-triage の起動で採点して整理し直します

<!-- dev-triage -->
```

## 着手済みのコメント

origin に `issue-<N>` ブランチがある (`/dev-impl` が着手したことがある) のに、状態のラベルが無い issue に書く。`/dev-impl` が `needs-human` で止めた issue から、人が `ready` を戻さずに `needs-human` だけを外した場合に起きる。

```markdown
**この issue は /dev-impl が着手済みです。状態のラベルを戻してください**

origin に `issue-<N>` ブランチがあるので、`/dev-impl` が実装を始めたあとに状態のラベルが外れたと判断しました。設計し直すと、着手済みの実装と食い違うおそれがあるため、整理し直していません。

- A (推奨): `/dev-impl` の止めた理由に回答済みなら、`needs-human` を外して `ready` を付ける。次の `/dev-impl` がブランチから再開します
- B: 設計からやり直す。`issue-<N>` ブランチを消してから `needs-human` を外すと、次の dev-triage の起動で整理し直します

<!-- dev-triage -->
```

## 整理に失敗したときのコメント

途中で失敗して状態を決められなかった issue に書く。ラベル無しのまま残すと、次の起動で同じ失敗を繰り返すため。

```markdown
**dev-triage がこの issue を整理できませんでした**

<失敗した手順と、エラーの全文か原因の 1〜3 文>

原因を直して `needs-human` を外すと、次の dev-triage の起動で整理し直します。

<!-- dev-triage -->
```
