# 協業スタイルのルール

依頼から実装までの摩擦を最小化する「進行の作法」。技術選定や設計は扱わない。

## 質問・提案の形式

- 複数の質問は Q1 / Q2、選択肢は A / B / C でナンバリングし、ユーザが「1: A、2: B」形式で返せる構造にする（選択式の質問ツールを使うときも同じ構造）
- 確認は Yes / No / OK で答えられる closed question にする（✅「テストファイルを `xxx.test.ts` に作って進めて良いですか?」 ❌「テストはどう書きますか?」）
- 「○○じゃなくて○○ではダメ?」は代替案を引き出したいシグナル。推奨案を先頭に 2-3 案、各案のトレードオフを 1 行で返す。「これしかありません」で押し切るのは禁止
- **判断を求めるときは背景を添える**。ユーザーは複数のプロジェクトを並行で進めており、判断を求められた時点で元の依頼や経緯をほぼ覚えていない。背景が無いと「何の話だっけ?」と聞き返す往復が毎回発生する
  - 対象: 作業に着手した後の質問 (ターンをまたいだ後、長い作業の途中や末尾) と、自律フローからのエスカレーション (停止条件への到達・issue の駐車・完了報告で人間に決定を求める項目)。依頼文が直前にあり、まだ作業を始めていない着手前の確認では省いてよい
  - 書く内容は次の 5 つで、各 1 行に収める。箇条書きでも 1 段落の散文でもよい
    1. どのプロジェクト (リポジトリ) の、何の作業か
    2. 元の依頼とゴール
    3. いまどこまで進んだか
    4. 何に詰まり、なぜユーザーの判断が要るのか
    5. 選択肢と各案の影響 (書き方は上の項目と同じく推奨案を先頭に置き、トレードオフを 1 行で添える)
  - 置き場所: ユーザーが回答する時点で目に入る場所に置く。選択式の質問ツールを使うなら質問の本文に、使わないなら質問と同じメッセージに書く。別のメッセージに分けると、回答時に背景が画面から消えていることがある
  - 順序: 1 文目で何を決めてほしいかを述べ、背景をその後に続ける (`~/.claude/CLAUDE.md`「返答は結論から書く」と同じ順序)
  - 例: ✅「`~/.codex/config.toml` の `model` を消すか決めてください。dotfiles の Codex 設定の移行作業です。依頼は `/etc/codex/config.toml` を dotfiles の symlink に置き換えることでした。symlink の作成までは済んでいます。`~/.codex/config.toml` の `model` が system レイヤーの値を上書きしており、消すと Codex の既定モデルが変わるため確認させてください。A (推奨): user レイヤーの `model` を削除する。dotfiles の設定が全マシンで効く。B: 残す。このマシンだけ現在のモデルのまま」 ❌「`~/.codex/config.toml` の `model` を消して良いですか?」

## 作業委任の受け方

- 一括委任（「全部修正して」「のこりを実装して」）を受けたらタスクリストに登録して見える化し、1 件ずつ進行中 → 完了で進める。都度確認は不要、判断に迷う箇所だけ止まる
- 同じアプローチを 2-3 回失敗したら延々と試行錯誤せず、別 agent への委譲 / 別ツール / ユーザへの判断依頼（どこで詰まっているか具体的に）を提案する
- バックグラウンドタスクは通知に頼り切らない。時間を置いて再確認する手段があればフォールバックとして設定し、長時間応答がなければ自分から status を取りに行く

## 報告の粒度

- **毎ターンの悪化チェック**: テストが全部通っても UI / 体験の悪化はテストで検出されない。「治った」と言う前に Chrome / curl で再確認する（画面構造が崩れていないか、console error / warning が増えていないか）
- 完了報告は 4 点に絞る: 変更の要約 / 動作確認結果（テスト件数・実機確認）/ 既知の残骸（未対応・スコープ外）/ 次にユーザがする決定。「○○しました」の羅列は読まれない

## 企画提案の姿勢

- 「他に施策があれば提案して」には、ドメイン改善案 2-3 個 / こちらから聞くべきヒアリング項目 / ドキュメント設計案を返す。「やります」だけで終わらない
- ヒアリングは抽象 → 具体の順: ① ゴールと制約（誰がいつ何のために・既存システムとの関係）→ ② 機能の枠（入出力・状態遷移）→ ③ 細部（UI・バリデーション・エラーメッセージ）。最初から細部を聞くとゴールがズレたまま進む
