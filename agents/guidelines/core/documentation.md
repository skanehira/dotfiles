# ドキュメント作業のルール（設計書・仕様書・README 等）

<!-- doc-check: skip-process -->

- 種別: ガイドライン (規範)

文書の書き方の規範を定める。文書ファイルを書く・直すときは、書き始める前に `/workflow-doc-write` を起動し、その手順で書く。Skill ツールを持たない subagent は `~/.claude/skills/workflow-doc-write/SKILL.md` を Read して同じ手順に従う。PR・issue の本文と、人に送る文面にも、この規範を当てる。

## 書くもの: 結論と、その理由

- 文書には、いま正しい結論と、その結論を選んだ理由を書く。読み手が知りたいのは何に決まったかとその理由で、決まるまでの流れは要らない
- 決定は次の形で書く。採らなかった案は、読み手が「なぜその案ではないのか」と思うものだけを挙げる

  ```text
  決定: <何に決めたか>
  理由: <なぜそれを選んだか>
  採らなかった案: <案> (<採らなかった理由>)
  ```

- 各節は結論の 1 文で始め、理由と詳細をその後に置く

## 書かないもの: 過程

過程にはそれぞれ置き場所がある。文書の本文には書かない。

| 書きたくなる情報 | 置き場所 |
| --- | --- |
| 変更の経緯 (「以前は〜だった」「〜に変更した」) | コミットログ、PR の本文 |
| 議論の途中経過、撤回した案 | 決定台帳 `docs/DESIGN_NOTES.md` (`/workflow-design-notes`) |
| 確認した日付、確かめていない範囲 | その文書の「依拠する外部事実」の表 |
| 作業中に行った検証の記録 | 完了報告 |

- PR の本文には変更内容だけを書き、issue の本文にはやることと完了の条件を書く。どちらにも作業の過程を書かない
- 議論しながら設計を固めるときは、完成文書を議論中に直接編集しない。決定台帳に追記し、節目に完成文書をゼロから作り直す (`/workflow-design-notes`)。議論のたびに完成文書へ書き足すと、文書が継ぎ足しで崩れる

## 読み手と型

- 書く前に、誰が何のために読むかを決める。作業の文脈を知らない読み手が読んで分かる言葉で書く
- 単一の標準フォーマットを機械的に当てはめない。文書の用途 (設計書 / テスト項目書 / 手順書 / README 等) と読み手に合った構成を決めてから書き始める
- 文書の冒頭メタ情報に**種別を明記**する (例: `- 種別: 設計書`)。監査でどの規範を当てるかの判定に使う
- 型別の構造規範が `~/.claude/guidelines/core/references/doc-formats/<型>.md` にあれば、それに従う。無い型は本ファイルの規範だけでよい

## 用語: 造語を作らない

- 技術の対象は、その技術の公式ドキュメントが使う用語で呼ぶ。日本語の言い回しに置き換えない (例: Kubernetes なら Service・Pod・Ready・エンドポイント。❌「結びつく相手」「振り分け先」「準備未完了」)
- 読み手が知らないかもしれない用語は、初めて出すときに用語のまま書き、短い説明を添える (例: 「Ready (readinessProbe に成功し、リクエストを受けられる状態)」)。説明の言い回しを用語の代わりに使い続けない
- 新しい名前を付けてよいのは、公式の用語も一般の開発用語も無い概念だけである。付けたら「用語・成果物一覧」に定義を書く。作業中に仮に呼んだ名前 (例: 「合意ゲート」「両表」) は文書に持ち込まない
- 同じ対象を文書の中で別の名前で呼ばない

## 全体整合 > 差分最小

- コードの「外科的変更」ルールはドキュメントには当てはめない。相互参照 (用語⇄定義、コンポーネント⇄フロー、約束⇄実装物) を持つ文書では、局所差分を小さくすることより文書全体の整合を優先する
- 概念の追加・削除・置換を含む改訂では、該当する節を最新の結論で書き直す。節の末尾に書き足さない。字句修正だけなら局所の Edit でよい
- 同じ事実は 1 か所にだけ書き、ほかの節からは節名で参照する
- 概念を削除・置換したときは、旧概念への参照の残りを rg で探して消す。存在理由が消えた記述に弱い理由を後付けして残さない

## 汎用原則 (全型共通)

- 相互参照の多い設計書には、整合を保つための 2 節を入れる。1 つは「用語・成果物一覧」(定義箇所・生成者・消費者の表) で、もう 1 つは「依拠する外部事実」(確認日つきの前提の一覧) である
- 表の数値列には単位を、選択肢列には取りうる値の例を書く
