# 検証コマンドのルール

テストに課している規律を、**検証・検出・計測のコマンドそのものにも課す**。

`testing.md` のリトマス試験 B (「テスト対象を no-op に置き換えても通るテストは何も検証していない」) は、テストコードだけの話ではない。変異検証・監視・状態確認・出力比較のコマンドにも同じことが起きる。そして**検出のバグは実装のバグより気づきにくい**。異常が無いのか、検出できていないのかが、結果だけを見ても区別できないからである。

## 原則: すべての検出に対照を取る

| 対照 | 問い | 取らないと何が起きるか |
| --- | --- | --- |
| **陽性対照** | 異常があるとき、この検出は本当に反応するか | 壊れた検出器が「異常なし」を返し続ける |
| **陰性対照** | いま異常が無いとき、この検出は静かか | 既に真の条件を監視して「検出した」と誤報する |

「検出できないこと」と「異常が無いこと」を区別できない検証は、実行しても情報が増えていない。

## 実際に踏んだ 5 つの失敗と対策

### 1. 変異が適用されていないのに結論を出した

文字列置換が空振りしたまま「テストが緑 = 変異を殺せなかった」と判定した。**実験そのものが成立していなかった。**

**対策: 変異検証は手で組まず `agents/scripts/mutate-check.ts` を使う。** baseline が緑であること・変異が実際にファイルへ適用されたこと・復元がバイト一致したことを対照として取り、1 つでも崩れたら `killed` / `survived` ではなく **`invalid`** を返す。exit code は `killed=0` / `survived=1` / `invalid=2` で区別できる。変異とテストは作業ツリーの複製の中で行い、原本は書き換えない。そのため、同じ作業ツリーでほかのエージェントがテストを並列に実行していても、変異中のコードを読まない。テストのコマンドは複製の根で実行されるので、パスは根からの相対で書く。原本のパスや `cd` を使うと、変異していないコードをテストして survived と誤って結論する。

```bash
agents/scripts/mutate-check.ts [--root <作業ツリーの根>] <file> <old> <new> -- <test command...>
```

手で書く場合も同じ 3 対照を必ず取る。`s.replace(old, new)` の前に `assert old in s` を置く。

### 2. コマンド置換で末尾改行を捨てた

`ACT=$(cmd)` は**末尾改行を捨てる**ため、`[ "$ACT" = "$EXP" ]` は末尾改行の欠落を原理的に検出できない。「一致」と表示されても差を見ていない。

**対策: 出力のバイト比較にコマンド置換を使わない。** ファイルに落として `cmp` する。

```bash
cmd > /tmp/actual.txt
printf 'expected\n' > /tmp/expected.txt
cmp /tmp/actual.txt /tmp/expected.txt
```

### 3. 監視のパターンが別の場所にマッチした

「修正が入ったら検知する」つもりの `rg -q 'pattern'` が、**別の箇所に元からある行**にマッチして即座に成立した。

**対策: 監視を仕掛ける前に陰性対照を取る。** そのパターンが**いま偽であること**を確認する。既に真なら検出器が壊れている。

```bash
rg -q 'pattern' target && echo "検出器が壊れている (既に真)" && exit 1
```

### 4. グロブが意図より広くマッチした

`agent-amember-10-*.jsonl` が `member-10-2` の分も拾い、同じファイルを 2 回見て「両者とも稼働中」と誤判定した。

**対策: セレクタは件数を検証する。** 1 件を指すつもりなら 1 件であることを確認し、正規表現で厳密に切り出す。

```bash
n=$(ls glob 2>/dev/null | wc -l | tr -d ' ')
[ "$n" -eq 1 ] || { echo "セレクタが $n 件にマッチ (想定 1 件)"; exit 1; }
```

### 5. ランナーが pass したテストの出力を隠した

エージェントから実行した vitest が、pass したテストの標準エラーを表示しなかった。CI では React の `act(...)` の警告が 868 件出ていたのに、手元では「警告 0 件」と数えた。vitest 5 は、実行元をエージェントと判定すると既定の reporter を `minimal` に替え、pass したテストの出力を出さない。**検出器が見えていないのに、異常が無いと結論した。**

**対策: 警告を数える前に、pass したテストの出力が見えることを陽性対照で確かめる。**

- pass するテストに既知の文言の警告を一時的に足して実行し (例: `console.error("PROBE-WARNING")`)、その文言が出力に現れることを見てから数える。現れなければ、すべての出力を表示する reporter を明示する (vitest 5 では `--reporter=default`)
- 作業ツリーを書き換えられないとき (並列のレビューなど) は、出力にテストファイルごとの結果の行が並ぶことで代える。pass したファイルの行を省く reporter は、pass したテストの警告も省く
- CI で出た警告が手元で出ないときは、先に手元のコミットが CI の対象のコミットと同じかを確かめる (`git rev-parse HEAD` と、CI が実行したコミットの SHA)。手元のブランチが古いと、警告を出すテストファイルがそもそも無い

```bash
# プロジェクトのテストコマンドに reporter を足して流し、警告の件数を数える
vitest run --reporter=default 2>&1 | rg -c 'not wrapped in act' || :
```

## 適用範囲

自分の作業の検証、他 agent の成果物の検証、オーケストレーションの状態確認のいずれにも適用する。とくに**一次証跡で判定する場面**では、証跡を取るコマンド自体が誤っていれば判定は無意味になるため、対照を省略しない。
